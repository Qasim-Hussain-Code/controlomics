# Contributing

Changes should identify the scientific problem, preserve explicit evidence states, minimize data transmission, and include meaningful checks. Keep examples small and clearly label hypothetical controls and synthetic outcomes. Do not add fabricated citations, claims of validation, raw private data, credentials, or unsupported performance values.

Use the local commands in README.md. Update schemas, exported JSON Schemas, ontology versions when appropriate, affected documentation, and tests together. Document consequential choices in `docs/adr/`. Automated systems are not project authors; preserve legitimate human authorship and contribution records.

Routine commit messages contain at most three concise words joined with underscores. Before committing, inspect status and the diff, check for secrets and private material, run relevant checks, and verify that documentation describes actual behavior. Use the configured Git identity. Do not publish or force-push without authorization.

The license is pending the owner's choice. External contribution and public release procedures will be finalized once it is selected.
