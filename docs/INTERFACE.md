# Local workspace interface

Version 0.6.5.dev0 restores the earlier preferred six-section workspace layout with a revised palette. Navigation names Analysis & claims, Controls, Evidence library, Execution, Scientific audit, and Evaluation. Open and Export keep file actions together; Save review bundle remains available in the header. The interface uses the existing local server and needs no frontend build step.

## Visual structure

A vertical navy navigation rail frames the scientific workspace. The light canvas retains the earlier overview, four record-count cards, and a responsive two-column control collection. Slate text, blue actions, neutral surfaces, and restrained ochre and burgundy accents revise the palette without replacing the workflow layout. The overview retains the complete scientific question and actual project and analysis identifiers. Its local conceptual SVG illustrates the claim, control, source, and result relationships; it represents no measurements, benchmark outcomes, or validation claim. System fonts and local assets keep the application self-contained.

Four summary cards are labeled Scientific claims, Control specifications, Publication records, and Completed executions. Controls include reviewed specifications and candidates; completed executions count results with COMPLETED execution status. Zero remains zero. A publication count does not imply statement support. A completed execution does not imply a passed control or a valid scientific claim. Summary actions open the corresponding section. Control numbers such as C01 reflect collection order, not scientific ranking.

Control cards retain an explicit Claim tested field, exact evidence-state labels, scientific rationale, expected behavior, failure interpretation, and limitations. Assumptions and provenance expand separately. The collection uses two columns above 900 pixels and a single column at narrower widths. Control class, scientific level, and evidence state are separately labeled; color remains supplemental. Positive controls use blue accents and negative controls use ochre. Unverified evidence uses ochre, conflicting evidence uses burgundy, and method review uses slate. Colors do not authenticate imported review receipts or establish scientific validity.

Search matches a control's name, rationale, expected behavior, identifier, or linked claim statement. The class filter uses the existing control ontology; a claim filter appears for multiple claims. An evidence-state filter uses the recorded state, and Clear filters restores the full collection. Filters combine without editing records, changing priorities, or promoting evidence status. A short state guide preserves the distinctions between review, source support, unresolved evidence, and scientific validity. When source review has no identity-checked publication, the collection explains that prerequisite and links to Evidence library. Control details display the full claim, while result panels name the executed control and challenged claim. Audit panels display the assessed claim. Result details retain IDs, assumptions, recorded parameters, seed, software versions, runner hash, and any prespecified rule.

Execution requires an explicit compatible reviewed-control selection. Rendering the same project preserves that selection when it remains eligible. A new project or the loss of eligibility returns the selection to its prompt; it does not silently choose another control. Availability guidance explains missing review, unsupported mappings, existing plans, or a missing CSV and provides links to inspect controls or specify the supported paired control. Package creation requires an eligible selection; local execution also requires a selected CSV. Interface availability does not replace server validation or scientific justification.

Execution fields follow the selected procedure. References ask for the expected effect and absolute tolerance; resampling asks for draws and seed, with coverage for bootstrap intervals. Procedure choice, expected values, resampling settings, and assumptions remain entered while selecting another control or refreshing the same project. The researcher must review their applicability to the selected specification; the interface does not infer new scientific values. An explicit CSV inspection shows dimensions and an original-byte hash in a restrained summary surface. Shape checking does not run a control or establish sampling assumptions. A separate JSON export retains only that summary.

Scientific reports retain their existing standalone layout, serif title, actual record summaries, internal links, mobile layouts, and print styles. Control and claim references resolve within the report. Empty sections remain explicit. No script, remote font, or external image is required. The workspace palette refresh does not alter the report's numerical or scientific content.

## Navigation and accessibility

The selected section has explicit tab and panel relationships. Navigation tabs use vertical orientation on desktop and mobile. Arrow keys, Home, and End move selection; only the selected navigation tab participates in normal Tab traversal. A skip link reaches the main workspace. The mobile drawer confines keyboard focus while the header and canvas are inert, closes with its close button, Escape, or the backdrop, and returns focus appropriately. File menus also close with Escape. Busy operations and errors announce their actual states.

Forms retain native labels, required fields, and unselected scientific categories. Review and judgment headings scroll below the fixed header. Opening a candidate editor, source review, or judgment workbench moves keyboard focus to its destination summary after any pending form lock ends. The selected view is keyboard focusable. The outbound-request dialog has an accessible name and description, initially focuses Cancel, and retains a deliberate Send this exact request action. Metric tables become labeled rows on narrow screens. The interface respects reduced-motion preferences and retains visible keyboard focus. Targeted small scientific labels, record notes, placeholders, and evidence states use darker text and selected larger sizes; this is a scoped readability change, not an accessibility certification.

## Local operation

No external images, fonts, UI libraries, analytics, or storage were added. Projects and form signatures remain in browser memory. Export needed tracks recorded revisions; Unrecorded inputs identifies edited form values, and reverting a form clears that state. Bundle prepared means a complete download was prepared, not verified on disk. Retain it before closing. The status also appears in the overview at narrow widths, while its live announcement remains available independently of the visual placement.

Forms and file selectors are temporarily inert while an operation is pending. Navigation and recorded views remain available. Closing the page during an operation triggers the existing unsaved-work warning. Failed and interrupted operations restore editable inputs; they never automatically repeat a request. A stale local server session is renewed without replacing the browser workspace. Retry the rejected operation explicitly. An interrupted approved external request may already have transmitted content and may lack a returned ledger.

Evaluation results display the complete recorded bundle SHA-256 and selected partition. Metrics exclude unrecorded judgment edits. Loading another validated bundle or selecting a different partition clears old metrics and disables their export until recalculation. Cancelled replacement preserves the earlier recorded bundle and report.

The browser checker requires the exact task-owned headless profile through `--profile` and accepts separate loopback server, debugging port, output, and download locations. It checks the profile before interactions or browser shutdown. Retained [reliability observations](validation/ui_checks.json) add metric invalidation, input locking, session renewal without replay, and interrupted-response handling to the earlier synthetic workflow checks. The interrupted hosted response is mocked; no hosted request or real reviewer annotation is submitted.

Opening another project or starting an empty workspace asks before replacement. Candidate and source-review switching, example/draft application, and evaluation replacement protect unrecorded form edits. Judgment tracking includes all cases; changing the visible case alone is not a new judgment. Accepted project replacement resets prior forms, reviews, evaluations, input selection, credentials, previews, and the ledger. Public literature and hosted reasoning requests still require exact-payload approval. See [USAGE.md](USAGE.md), [PRIVACY.md](../PRIVACY.md), and [SECURITY.md](../SECURITY.md).
