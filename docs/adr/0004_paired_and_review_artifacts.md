# ADR 0004: Explicit paired adapter and bounded local review artifacts

## Problem

A generic mean-difference runner cannot reproduce arbitrary statistical specifications. Paired input needs pair-preserving procedures and distinct assumptions. Evaluation JSON editing and separate project/ledger exports also impede local review.

## Alternatives

Loosen generic adapter eligibility, execute generated code, add a full scientific computing stack, or treat paired data as independent groups. None makes an arbitrary specification applicable. A database could persist work but adds maintenance and privacy costs without a present need.

## Decision

Retain the independent-group technical gate. Add a fixed complete-pair control specification, explicit adapter identifier and applicability rationale, bounded complete-pair CSV parser, sign-flip permutation and whole-pair percentile bootstrap. Add a local supplied-judgment workbench and exact snapshot binding. Store inspectable review archives with a typed network ledger, fixed members, hashes, and bounded in-memory restore.

## Scientific rationale

Pair preservation is necessary but insufficient for valid inference. Independent pairs and sign invariance under the tested permutation null require justification; zero mean alone does not establish the latter. Percentile coverage remains unestablished. Review attestations do not authenticate expertise. Dataset references and imported predictions remain distinct from editable recommendation and evidence reference judgments.

## Technical rationale

Standard-library implementations fit the resource constraints and existing fixed-code execution model. Typed records and manifest checks provide inspectable consistency. The archive never executes or extracts imported HTML, scripts, or arbitrary paths.

## Privacy and security

Raw numeric inputs and full source texts remain outside review archives. Credentials and raw outbound bodies are rejected from the ledger. Project descriptions remain potentially sensitive. Loopback authorization and body budgets apply to new API actions. Hashes do not authenticate maliciously replaced manifests or prove ledger completeness.

## Limitations and reconsideration

This adapter does not handle nested, temporal, adjusted, or primary analyses. Archived revision hashes cannot recover prior content. Reconsider the limits when independently justified workflows, larger retained records, authenticated provenance, or a separately assessed hosted deployment require them. Independent expert and biological validation remain separate research work.
